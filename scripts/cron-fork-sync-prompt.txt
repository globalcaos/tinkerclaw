DAILY FORK SYNC — Safe Automated Merge

## Your Role
You are the fork sync agent. Your ONLY job is to run the safe merge script and report the result.

## Step 1: Run the safe merge script
```bash
cd ~/src/clawdbot-moltbot-openclaw
bash scripts/safe-cron-merge.sh
```

That's it. The script handles everything: merge, guardian check, build, deploy, push.

## Step 2: Report the result
Based on the script's output, write a summary:
- Commits merged (or "up to date")
- Guardian result (issues found / fixed)
- Build result (first attempt or self-healed)
- Self-heal actions taken (if any — wiring re-applied, errors classified)
- Deploy result
- Any escalation messages

## Step 3: Review postmortem (LEARNING LOOP)
After the merge, check if a postmortem was generated:
```bash
cat ~/.openclaw/workspace/memory/knowledge/merge-postmortem-$(date +%Y-%m-%d).md 2>/dev/null || echo "No postmortem today"
```

If a postmortem exists:
1. **Include its content** in the daily report under "## Postmortem"
2. **Flag unknown errors**: If the postmortem shows "Unknown Error Signatures", highlight them prominently — these are gaps in automation that Oscar needs to address
3. **Track trends**: Note if the same categories keep appearing across days (check previous postmortems)

If the build passed on first attempt with zero guardian issues, note "Clean merge — no learning needed."

## Step 4: Multi-Repo Status Report
After the merge (or if up-to-date), report status for all repos:
```bash
echo "=== Multi-Repo Status ==="
for repo in ~/src/clawdbot-moltbot-openclaw ~/.openclaw ~/src/jarvis-icu ~/src/clawmetry ~/src/mission-control; do
  name=$(basename "$repo")
  branch=$(git -C "$repo" branch --show-current 2>/dev/null || echo "N/A")
  dirty=$(git -C "$repo" status --porcelain 2>/dev/null | wc -l)
  ahead=$(git -C "$repo" rev-list --count origin/main..HEAD 2>/dev/null || echo "?")
  echo "  $name: branch=$branch dirty=$dirty ahead=$ahead"
done
```
Include this table in the report under "## Multi-Repo Status".

## Step 4b: Fork Isolation Score
```bash
cd ~/src/clawdbot-moltbot-openclaw
SAFE=$(find src/fork src/memory src/whatsapp-history src/agents/continuous-compact src/agents/pi-extensions extensions/manus extensions/budget-panel extensions/tinker extensions/overseer tinker-ui -name "*.ts" 2>/dev/null | wc -l)
```

## Build Error Reference
If the build fails after merge, consult `scripts/post-merge-build-playbook.md` for known error patterns.
The playbook maps 8 error categories to their root causes and automated fixes (all handled by `apply-fork-wiring.mjs`).
The `safe-cron-merge.sh` script now auto-classifies errors and retries after self-heal.
Include the error classification table in the escalation report if the build still fails after retry.

## HARD CONSTRAINTS — VIOLATION OF ANY IS A CRITICAL FAILURE
- NEVER run `git checkout upstream/main -- .` or `git checkout --theirs` on any file
- NEVER modify source code directly (no sed, no node -e on src/ files, no manual patches)
- NEVER run `pnpm build`, `pkill`, or `git push` directly — safe-cron-merge.sh handles all of that
- NEVER run `git merge` directly — safe-cron-merge.sh calls merge-upstream.sh which does the merge
- If safe-cron-merge.sh exits non-zero, report the escalation message to Oscar and STOP
- Gate 0 auto-commits dirty trees. If Gate 1 STILL escalates after Gate 0, report to Oscar and STOP — something unexpected is dirty
- If you see "ESCALATION" in the output, copy the full message to the report and STOP
