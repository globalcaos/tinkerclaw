# AMYGDALA Training Guide

## Privacy Notice

The Personality networks are trained on YOUR personal interaction history. The resulting model weights, training databases (`training.sqlite`), and personality nudge files encode your communication style and preferences.

**NEVER commit personality model files to a public repository.**

Prudence networks are trained on public AI incident data and are safe to share.

The `.gitignore` is configured to exclude personality model files automatically.

## Network Families

AMYGDALA uses two families of lightweight ONNX neural networks:

### Prudence Networks (Public — Safety)

Five networks (prudence-a through prudence-e) trained to gate dangerous actions. These are **publicly available** and can be downloaded from the release artifacts.

- **Purpose:** Block actions matching historical failure patterns before the LLM finishes reasoning
- **Input:** 384-d situation embedding (frozen mxbai-embed-large encoder)
- **Output:** Block probability (0.0 = safe, 1.0 = dangerous)
- **Training data:** Operational incident logs — destructive file operations, unsafe git commands, credential exposures
- **Size:** ~50KB per network

**To use pre-trained prudence models:**

```bash
# Download from release artifacts
mkdir -p models/amygdala/
# Place prudence-a.onnx through prudence-e.onnx in models/amygdala/
```

### Personality Networks (Private — Behavioral)

Five networks (personality-a through personality-e) that modulate agent behavior per-user. These are **private** — they encode your specific interaction patterns and preferences. You must train your own.

- **Purpose:** Adapt tone, verbosity, tool preferences, and communication style to the specific user
- **Input:** 384-d situation embedding
- **Output:** Behavioral modulation vector (64-d embedding)
- **Training data:** Your agent's operational logs — successful interactions, user corrections, preference signals
- **Size:** ~50KB per network

## Training From Scratch

### Prerequisites

- Python 3.10+
- PyTorch
- ONNX Runtime
- Training data: operational logs in JSONL format (session transcripts)
- Ollama with `llama3:8b` (for KD pre-training teacher labels; optional, heuristic fallback available)
- SQLite database with mined examples (generated by `mine_history.py`)

### First-Run Bootstrap

Training follows a multi-phase pipeline. For a cold start with no prior models:

#### Step 1: Mine Historical Data

Extract labeled training examples from deployment session transcripts. Targets 2,000-5,000 labeled examples from ~4 months of history.

```bash
cd training/amygdala/

python mine_history.py \
  --sessions ~/.openclaw/sessions/ \
  --db ../../data/amygdala/training.sqlite \
  --dry-run   # preview first, then remove --dry-run
```

This populates the `mined_examples` table in `training.sqlite`.

**Minimum data requirements:** ~2,000 examples for basic convergence, ~5,000 for robust generalization. With fewer than 1,000 examples, models will overfit.

#### Step 2: Knowledge Distillation Pre-training (Personality only)

Cold-start Personality networks using a local LLM as teacher. This gives the personality networks a sensible initialization before PPO fine-tuning.

```bash
python kd_pretrain.py \
  --db ../../data/amygdala/training.sqlite \
  --models-dir ../../models/amygdala/ \
  --epochs 30
```

Requires Ollama running locally with `llama3:8b`. If Ollama is unavailable, falls back to heuristic labels based on situation context (less accurate but functional).

Output: `models/amygdala/personality-{a-e}-kd.pt` (KD-initialized checkpoints)

#### Step 3: Supervised Pre-training (All Networks)

Pre-trains all 10 networks (5 Prudence + 5 Personality) using supervised learning.

```bash
python pretrain.py \
  --db ../../data/amygdala/training.sqlite \
  --models-dir ../../models/amygdala/checkpoints/ \
  --epochs 50
```

Key design choices:

- Prudence loss: asymmetric weighted CrossEntropy (w_stop=10, w_allow=1, w_escalate=3)
- Personality loss: MSE + lambda \* target_vector_pull (lambda=0.3)
- Early stopping with patience=10
- Hyperparameter search: LR in {1e-3, 3e-4, 1e-4}, dropout in {0.0, 0.1, 0.2}
- Best checkpoint saved per architecture

If KD weights exist from Step 2, pass `--kd-weights-dir` to initialize personality networks from them.

#### Step 4: Export to ONNX

Export all 10 trained PyTorch networks to ONNX for runtime inference.

```bash
python export_onnx.py \
  --checkpoints-dir ../../models/amygdala/checkpoints/ \
  --output-dir ../../models/amygdala/onnx/
```

Each export is verified by running a forward pass through both PyTorch and ONNX Runtime (max absolute error < 1e-4).

### Data Format

Each training sample is a JSON object:

```json
{
  "situation": "tool=Bash args='rm -rf /tmp/cache' session=agent:main:main",
  "label": 1,
  "category": "destructive_operation"
}
```

For prudence: `label=1` means "should have been blocked", `label=0` means "safe action."
For personality: labels are behavioral preference scores (0.0-1.0).

### Personality Target Vector

The personality networks are pulled toward a **target vector** during training. This vector defines the desired communication style along 5 dimensions, each in the range [-1.0, +1.0]:

| Dimension       | -1.0                    | 0.0     | +1.0                     |
| --------------- | ----------------------- | ------- | ------------------------ |
| `verbosity`     | Very terse              | Neutral | Very verbose             |
| `formality`     | Very casual             | Neutral | Very formal              |
| `hedging`       | Very assertive / direct | Neutral | Very hedging / uncertain |
| `emoji_rate`    | No emoji                | Neutral | Frequent emoji           |
| `assertiveness` | Passive / deferential   | Neutral | Confident / direct       |

**Example target vector** (default operator persona):

```python
target_vector = [
    -0.2,  # verbosity: somewhat terse
    -0.3,  # formality: casual-leaning
    -0.4,  # hedging: direct
    -0.6,  # emoji_rate: minimal emoji
    +0.4,  # assertiveness: confident
]
```

Pass the target vector to `pretrain.py` via `--target-vector` or set it in the training config. If omitted, defaults to zeros (neutral on all dimensions).

The target vector pull strength is controlled by `target_lambda` (default 0.3). Higher values bias the model more strongly toward the target at the cost of fitting observed data less precisely.

### Conformal Prediction Calibration

After training, calibrate uncertainty bounds for Prudence networks:

```bash
python conformal.py \
  --db ../../data/amygdala/training.sqlite \
  --checkpoints-dir ../../models/amygdala/checkpoints/ \
  --alpha 0.05
```

This ensures the model's confidence intervals are statistically valid (coverage guarantee >= 1-alpha under exchangeability).

### Online RL Fine-tuning (PPO)

After supervised pre-training, Prudence networks can be further refined via PPO:

```bash
python ppo_trainer.py \
  --db ../../data/amygdala/training.sqlite \
  --checkpoints-dir ../../models/amygdala/checkpoints/
```

State: situation embedding sequence [K=32, 512]. Action: gate decision in {stop, allow, escalate}. Reward: scalar derived from deployment outcomes (see `reward_labeling.py` and `nightly.py`).

### Nightly Retraining

The `nightly.py` orchestrator runs the full retraining cycle, designed to be called by CEREBELLUM's nightly cron:

1. Batch reward labeling (label today's unlabeled evaluations)
2. Fine-tune all 10 networks (1-3 PPO epochs + 3 supervised epochs)
3. Recalibrate conformal prediction (rolling 30-day window)

## Phase Deployment

| Phase       | Behavior                      | Risk                             |
| ----------- | ----------------------------- | -------------------------------- |
| 1 (observe) | Log decisions, don't block    | Zero — passive monitoring        |
| 2 (warn)    | Block + require user approval | Low — user confirms              |
| 3 (enforce) | Block automatically           | Medium — may block valid actions |

Start at phase 1. Review logs. Promote to phase 2 when false positive rate < 5%.

## Rule-Based Fallback

When ONNX models are unavailable, AMYGDALA falls back to rule-based heuristics:

- Blocks `rm -rf` patterns
- Blocks `git push --force` to main/master
- Blocks credential file modifications
- Warns on `DROP TABLE`, `DELETE FROM` without WHERE

This fallback ensures safety even without trained models.
