The asymmetry that matters

Write How it is issued Consequence
ENGRAM event append appendFileSync — event-store.ts:106,114 Returns only once the OS has the bytes. Survives a process crash. Not fsync'd, so a host power-loss can still lose the tail.
Everything in onTurnComplete attempt.ts:3540 — called without await, then .catch(err => log.warn(...)) Fire-and-forget. If the turn ends and the process exits, this may never run — and if it throws, the only trace is one warning line. Nothing retries it.

That single missing await is the difference between the two colours above. It is a deliberate latency trade — the user's reply is not held hostage to a bookkeeping write — but it means the forensic record is best-effort, and any reasoning that assumes "the turn finished, therefore the trace exists" is unsound.

Writes that are dead rather than deferred

A third category, and the reason this page exists rather than a tidy diagram: some writes never happen at all, while their instrument reports healthily. attempt-hooks.ts:49-51 records that emitPrePromptAnatomy also calls insertAnatomyEvent but has zero callers — so the eeg:anatomy-write instrument is deliberately bound to the onTurnComplete insert instead. And attempt-hooks.ts:411-429 notes the reasoning trace is consumed from a stash that, until a producer calls stashReasoningTrace, is never filled — so the reasoning_tree_state event is inert by data, not by code.
